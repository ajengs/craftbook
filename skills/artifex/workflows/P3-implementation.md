# P3 — Implementation

**Codex execution:** The umbrella creates a separate top-level phase chat under the initiative's one-time creation/coordination authorization. This phase is not a native subagent. Finalize all writes, then report the result path through the cross-session channel in `references/orchestration.md`, Result delivery. If creation or coordination was declined, the user launches the router's `manual_session` handoff and relays its result path. Other hosts keep their existing isolated-worker mechanism.

**Entry:** Approved specs and the completed implementation handoff, with exact revisions and no blocker, reported by a P2 session, or, for a bug, the diagnosis and handoff reported by a D1 session (`workflows/D1-bug-investigation.md`). The verification contract is not required to start. **Start:** The umbrella spawns an isolated implementation worker from the handoff, automatically, when that checkpoint arrives. On Codex this is an independent P3 session; other hosts retain their isolated implementation worker. The branch and working directory are the ones the user confirmed in the handoff, or, where the handoff left them open, the values the umbrella passes as `handoff_context`, which replace the handoff's placeholders. If another phase worker is active and the two can't run in parallel (`SKILL.md`, Coordination), this one waits. **Owner:** The umbrella coordinates, the implementation worker does the work, and the user retains design authority.

**Codes:** internal codes stay in notes. Keep them out of code, tests, commits and the PR (`policies/core.md`).

1. Before starting, the umbrella confirms the authorized milestone scope, exclusions, controlling artifact revisions, coordination route and project coding/testing conventions. It starts one isolated implementation worker from the controlling handoff, giving it the handoff by path and revision without restating or expanding it; the router records the run.
2. The implementation worker implements the agreed change. It chooses routine implementation tactics as needed, but does **not** invent requirements, abstractions or extra edge-case coverage.
3. The implementation worker runs appropriate local checks, preserves useful results and notes anything not run.
4. If the implementation worker finds a **new design decision**, it pauses affected work and reports the question, realistic options, trade-offs and recommendation to the umbrella, which asks the user and waits for the decision. Independent work may proceed safely. If material, update and reapprove the affected specs and any existing affected verification contract through P2 before proceeding. For a bug on the direct or reproduced path, a design decision, or a change that doesn't turn the reproduction green, sends it back to D1 on the confirm path; that isn't a rework. When the user's decision accepts or defers a limitation without changing an approved spec row, the umbrella sends it to the P2 session as a change request for the tradeoffs register (`standards/design.md`), with the user's words and the date. The phase worker continues from that decision; the handoff isn't regenerated.
5. If the implementation worker finds an unanticipated edge case, it assesses whether approved behavior already requires it; otherwise it reports the case as a finding to the umbrella and applies the scope policy. It does not automatically implement it.
6. The implementation worker opens the PR **ready for review, not as a draft**, once the change and its unit tests are in. Explicit VER integration tests are P5 scope. It reports the open PR to the umbrella, which starts P4 without waiting for CI.
7. **After the PR is open**, the umbrella polls CI until it passes (`SKILL.md`, Polling belongs to the umbrella). When a fix is needed, it starts a new implementation worker after the previous run has finalized its result; that phase worker debugs, fixes, pushes and reports the push to the umbrella.
8. Once CI has passed, the umbrella polls the PR's threads **every 3 hours** until the PR is completed, following `standards/pr-feedback.md`. Feedback also includes P4 findings and P5 failures that point to P3. When a fix is needed, the umbrella starts a new implementation worker after the previous run has finalized its result. The phase worker verifies, fixes, pushes, replies and reports to the umbrella. If a thread needs the user's input, the phase worker reports it and the umbrella asks the user. Whether a push starts a review round is the umbrella's call (`SKILL.md`, Which pushes start a review round).
9. The implementation worker ends by writing its result file to the `result_path` it was given (`references/orchestration.md`, Result file): `completed` with the pushed head and PR, `needs_decision` with the question, or `blocked`. The result file's summary covers the change, checks and results, deviations and any decisions. On Codex it messages the finalized path to the umbrella (`references/orchestration.md`, Result delivery); the umbrella passes it to the router; the umbrella reconciles decisions into `state.json`.

**Finishing without an agent.** When a `blocked` or `needs_decision` result goes to the user and their answer leaves no implementation work, for example they opened the PR the agent couldn't, the umbrella records the outcome itself with `event complete` (`references/orchestration.md`, Exceptions) instead of starting another phase worker to write it down. The router checks the head against the remote as it would an agent's result. Anything that still needs a commit goes back to a phase worker.

**Rework:** The umbrella starts a new implementation worker from the same handoff when the previous one has ended, giving it the findings or feedback to address. Reworks stay within the caps in `SKILL.md`.

**Output:** The PR and an execution summary with evidence; no mandatory standalone implementation report.

**Exit:** Approved scope is implemented, the PR is open with CI passing, and known gaps are explicit. The umbrella keeps polling threads until the PR is completed. Unresolved blocking design choices prevent a clean exit. P4 handles independent review.
